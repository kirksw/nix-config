# feat-tool-named-mcp-skills

> Give every work MCPorter CLI a dedicated, tool-named skill with focused operational guidance.

## Status

- [x] Plan
- [x] Implement
- [x] Test
- [x] Complete

## Context

The shared `work-mcp` skill explained how to invoke generated MCPorter wrappers, but it did not provide enough tool-specific trigger and usage guidance.
The existing dedicated skills were inconsistent: `linear` matched its server, while `recruiting` represented disabled Teamtailor access and `platform-status` combined Grafana and Hubble.
Agents need predictable discovery through skill names that match the underlying tools.

## Plan

### Scope

This change affects skill definitions under `agents/defs/skills/`, the default skill catalog in `agents/presets/default.nix`, and the work profile skill allowlist in `agents/presets/profiles.nix`.
The generated wrappers under `agents/defs/skills/work-mcp/generated/` remain the single generated source and were not regenerated by this change.

### Approach

1. Add one model-invoked skill for every configured MCPorter wrapper: `1password`, `google-drive`, `granola`, `grafana`, `hubble-mcp`, `linear`, `lunar-skills`, `slack`, `sourcegraph`, and `swe-pruner`.
2. Keep `work-mcp` as shared invocation, output-bounding, authentication, and mutation-control infrastructure.
3. Replace the generic `recruiting` skill with a tool-named `teamtailor` availability skill while Teamtailor remains disabled.
4. Remove `platform-status` from the catalog and profile because its guidance moves into the separate `grafana` and `hubble-mcp` skills.
5. Register and allowlist every tool-named skill, then validate structure, generated wrapper metadata, profile synchronization, and flake evaluation.

### Risks

Each model-invoked skill adds a short description to the agent context, so descriptions and bodies remain concise.
Tool schemas can change independently of the skills, so examples use command names from the current generated artifacts and direct the agent to command-specific help for exact flags.
Grafana currently uses MCPorter's typed-client fallback rather than a bundled CLI, but the shared runner presents the same server-oriented interface.
Teamtailor has no active MCPorter wrapper, so its skill reports disabled status and does not imply tool access.

## Testing

Commands run successfully:

```sh
nixfmt agents/defs/skills/*/default.nix agents/presets/default.nix agents/presets/profiles.nix
./scripts/check-structure.sh
git diff --check
node agents/defs/skills/work-mcp/generated/sourcegraph.cjs __mcporter_inspect
node agents/defs/skills/work-mcp/scripts/run.mjs sourcegraph keyword-search --help
node agents/defs/skills/teamtailor/scripts/status.mjs
nix run .#sync-agents
nix flake check --no-build --option eval-cache false
```

Targeted audits confirmed that every generated server has a matching skill, every documented example names a generated command, and representative prefixed mutation commands are blocked without `MCP_WRITE_CONFIRMED=1`.
The synchronized work profile contains all tool-named skills, omits `recruiting` and `platform-status`, and runs Sourcegraph command help through the installed bounded runner.
The full flake check passed in a clean worktree containing only this change after `sync-agents` built the generated agent source derivation.
In the main working tree, the same check remains blocked by an unrelated modified `hosts/nixos/ry4a/agent-microvms.nix` derivation named `nix-config-personal-agent-src`; a read-only review concluded that existing validation guidance is sufficient and no documentation guardrail change is warranted.

## Summary

### What changed

- Added dedicated tool-named skills for all ten generated work MCPorter CLIs.
- Replaced `recruiting` with the status-only `teamtailor` skill and split `platform-status` guidance into `grafana` and `hubble-mcp`.
- Standardized Linear on the shared generated wrapper and removed its duplicate generated CLI and runner.
- Kept `work-mcp` as shared infrastructure and strengthened its mutation detection for prefixed hyphenated and underscored command names.
- Registered and allowlisted every tool-named skill in the default preset and work profile.

### What was tested

- Structure, formatting, whitespace, frontmatter, skill registration, generated command names, mutation blocking, Teamtailor disabled status, profile synchronization, installed Sourcegraph help, and clean-worktree flake evaluation.
