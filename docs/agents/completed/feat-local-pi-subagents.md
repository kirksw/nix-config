# feat-local-pi-subagents

> Vendor `pi-subagents` so generated legacy configuration disables bundled agents.

## Status

- [x] Plan
- [x] Implement
- [x] Test
- [x] Complete

## Context

`~/.pi/agent/subagents.json` is generated by nix-agents, but `pi-subagents` 0.34.0 only read `settings.json`; its bundled agents remained enabled.

## Plan

### Scope

- `agents/packages/pi-subagents/`
- `agents/base-settings.nix`

### Approach

1. Vendor `pi-subagents` 0.34.0.
2. Read legacy `subagents.json` only when `settings.json` is absent.
3. Use the vendored package for every Pi profile.

### Risks

- Pi sessions must restart after syncing to load the local package.
- A future upstream update should either carry this compatibility behavior or replace the local package reference.

## Testing

```sh
node --experimental-strip-types --input-type=module ... # legacy config disables builtins
nix flake check --no-build
nix run .#sync-agents
```

## Summary

### What changed

- Added vendored `pi-subagents` at `agents/packages/pi-subagents/`.
- Added a read-only compatibility fallback from `settings.json` to `subagents.json`.
- Replaced both npm package references with the vendored package.
- Force-added two `result-*.ts` source files ignored by the repository-wide pattern; without them Pi could not load the extension.

### What was tested

- Legacy `subagents.json` disabled all builtins in direct discovery.
- `nix flake check --no-build` passed.
- `nix run .#sync-agents` passed and generated the local package reference.
- `pi -p` loaded the vendored extension successfully.
