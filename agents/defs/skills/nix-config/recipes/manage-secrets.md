# Manage secrets and providers

1. Identify whether the task needs a credential at Pi launch or a SOPS-managed secret for a host/service. Never print secret values or commit plaintext; inspect metadata and paths only.
2. For Pi providers, read `agents/pi-profiles.nix` and `modules/home/programs/ai-agents.nix` before changing them. Current providers use `credentialSource = "env"`, `credentialRef` for a preexisting environment variable, and `envVar` for the variable exposed to the tool. Add the provider name to the relevant base's `providers` list; profiles select a base, not providers directly. The wrapper exports only nonempty source variables and does not decrypt SOPS, query keychains, or fetch vault items. For a new backend, first implement and validate wrapper support; do not just set `credentialSource` to a backend name.
3. For SOPS secrets, read `docs/SECRETS.md` and `.sops.yaml`. Edit encrypted files with `sops`, verify the file path matches a creation rule and the intended recipients, then declare and reference the secret through the appropriate Nix module (for example, `config.sops.secrets."api/litellm/api-key".path` in `modules/home/programs/ai-agents.nix`). Keep credentials out of Nix strings and store derivations.
4. Validate configuration without exposing values using `validate-and-sync.md`. Confirm availability in the intended scope without printing the credential.
